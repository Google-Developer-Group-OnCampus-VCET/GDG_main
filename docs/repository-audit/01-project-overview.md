# 01 — Project Overview

## Purpose

The repository is named `gdg` (`package.json:2`) and was bootstrapped with `create-next-app` (`README.md:1`). `CLAUDE.md` describes it as the "GDG on Campus VCET chapter website." In its current state, verified by reading the code, it is two things layered together:

1. A **public chapter marketing site** — home, events, team, about, join, contact, resources, certificate lookup (`src/app/page.tsx`, `src/app/team/page.tsx`, `src/app/events/page.tsx`, `src/app/about/page.tsx`, `src/app/join/page.tsx`, `src/app/contact/page.tsx`, `src/app/resources/page.tsx`, `src/app/certificates/page.tsx`).
2. A **self-hosted, single-tenant event-operations platform** bolted on in the commit `c4ada08 feat: implement multi-event workshop platform with registration, check-in, and analytics` (per git log) — an `/admin` back office, session-cookie auth, a SQLite database, and public registration/check-in/certificate-verification APIs (`src/app/admin/**`, `src/app/api/**`, `src/lib/db/index.ts`, `src/lib/auth/index.ts`).

The "multi-tenant" framing in `docs/MULTI_TENANCY.md` is **aspirational, not real**: every query defaults to the literal string `"gdg-vcet"` as `chapter_id` (e.g. `src/lib/db/index.ts:979`, `:1170`, `:1238`, `:1777`), there is exactly one row ever seeded into the `chapters` table (`src/lib/db/index.ts:282-299`), and no code path accepts a chapter identifier from the request (subdomain, header, or session) to switch tenants. This is a single-tenant app with a `chapter_id` column present for *future* multi-tenancy, not an operating multi-tenant system. Treat `docs/MULTI_TENANCY.md` claims as a design intent document, not a description of shipped behavior.

## Notable Structural Observations (UNVERIFIED items flagged)

- **Dual, overlapping docs sets** in `docs/`: an uppercase set (`ARCHITECTURE.md`, `DATABASE_SCHEMA.md`, etc.) describing the platform build, and a lowercase set (`design-brief.md`, `design-reference.md`, `content-needed.md`, `implementation-plan.md`) describing the original chapter-site brief referenced by `CLAUDE.md`. They were not reconciled — `CLAUDE.md`'s brand/content rules (no invented team/events/stats) sit alongside a database seed (`src/lib/db/index.ts:381-430`) that inserts 124 synthetic "Student Developer #N" attendees and fabricated names/emails directly into the production-shaped `registrations` table. This is a direct tension between the content rule and the platform's demo-seed behavior — flagged here, detailed further in `09-business-logic-workflows.md` and `10-security-audit.md` (other forks).
- `data/gdg.db*` — a live SQLite database with WAL/SHM files — is present in the working tree. Whether it's gitignored is UNVERIFIED by this file; check `.gitignore` directly if provenance matters.
- `README.md` is the unedited `create-next-app` template; it describes none of the actual project. This audit's own `README.md` (sibling file) supersedes it for audit purposes only.
- No `middleware.ts` exists anywhere in `src/` or the repo root — confirmed by directory listing. This has direct authentication consequences, detailed in `05-authentication-authorization.md` and `10-security-audit.md` (other forks); flagged here as a structural absence.
